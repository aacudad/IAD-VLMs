Corpus Generation / Trace-Writing Prompt

Teaching Gemini to write a training trace

Every AnomalyThink reasoning trace starts as a single Gemini call: one product image in, one <think> block out. The system prompt casts Gemini as a senior industrial inspector and forces it through a fixed six-phase inspection flow before it's allowed to conclude — plus a controlled vocabulary, an internal 0–2 self-scoring rubric, and six hard auto-reject rules, all run silently before the trace is returned.

The six-phase reasoning template

The prompt's REASONING STRUCTURE section requires the <think> block to move through six phases, A→F, in order — evidence has to surface before the verdict does.

A
Task framing
  • identify the product
  • recall the visual properties that matter for this kind of part
B
Global scan
  • inspect overall shape, boundaries, surface continuity, and key features
C
Focused inspection
  • inspect critical regions in a sensible order
  • describe normal regions as well as suspicious ones
D
Evidence evaluation
  • if something looks wrong, slow down
  • describe shape, color, texture, boundary, alignment, continuity, material change
  • compare against nearby normal structure or expected geometry
E
Alternative check
  • consider reflection, lighting, printed marking, intended geometry, or harmless variation
F
Decision
  • determine anomalous vs. normal
  • if anomalous: best-supported location + type
  • if normal: why the inspected regions show no defect evidence

Eleven hard rules behind every trace

Independent of the six-phase flow, these constraints shape tone, honesty, and what the trace is allowed to claim.

Rule 1
Single-image independence
No "another / next / previous / similar to the earlier one" — every trace must read as the only image inspected.
Rule 2
No metadata leakage
Hidden GT labels may be supplied, but the trace can never say "the annotation indicates" / "I was told."
Rule 3
Evidence before conclusion
Identify → describe → compare → rule out alternatives → conclude. Never name the defect first.
Rule 4
Don't invent unseen history
"This may be abrasion" is allowed; "this occurred during solder reflow" is not, unless directly visible.
Rule 5
Natural, controlled voice
First-person internal reasoning; no theatrical suspense, repetitive hesitation, or generic scan narration.
Rule 6
Length: 120–200 words
Shorter is fine for a clear/simple image; longer only when genuinely ambiguous. No padding to hit the target.
Rule 7
Open with the product type
"Okay, I'm looking at this audio jack" — identify the object immediately if the type is provided.
Rule 8
Reference image as aid, not proof
The normal reference (Image 3) anchors expected appearance; never say "the reference image proves."
Rule 9
Region cue as aid, not proof
A highlighted region must still be visually justified — never assumed defective on cue alone.
Rule 10
Normal cases must stay specific
No generic "looks fine" — name the inspected regions and explicitly note the absence of anomaly indicators.
Rule 11
Acknowledge ambiguity
Blur, glare, shadow, or reflection uncertainty is stated inline — a verdict is still required, just not faked confidence.

Self-scoring gate, run silently before the trace is returned

Gemini scores its own draft on 8 categories (0/1/2), then accepts, or rewrites and retries. Hover a box for what that score means in that category.

Accepted only if: no auto-reject rule fires, total ≥ 13/16, and Visual Grounding, Evidence Before Conclusion, Single-Image Independence and Output Structure Correctness all score 2 — plus Decision Quality = 2 for anomalous images, or both Visual Grounding and Decision Quality = 2 for normal images.

Six auto-reject rules — instant fail, independent of score

These fire regardless of total score; A and B are the same leakage concerns as hard rules 1–2, restated as hard stops.

A · Batch/sequence leakage
implies another image, a previous/next/final item, a batch, or ordinal position
B · Metadata leakage
mentions or implies labels, annotations, hints, ground truth, or being told the answer
C · Evidence-order failure
names the defect before describing the visual evidence that supports it
D · Wrong output structure
missing image_id/reasoning, missing required tags, extra content after </think>, or invalid JSON
E · Unsupported defect claim
anomaly asserted without concrete visible evidence in the reasoning
F · Overstated causality
an unseen cause stated as definite fact rather than a cautious possibility

If it fails: rewrite priority, not a blank retry

On failure, Gemini fixes the lowest-scoring categories first — full regeneration is reserved for leakage, unsupported claims, or broken structure.

Remove any batch or metadata leakage
Reorder reasoning so evidence appears before conclusion
Replace generic statements with image-specific visual details
Remove unsupported causal claims
Strengthen justification for normal-case acceptance, or anomalous location/type
Correct output structure
Scope of this page
  • This documents prompts/inspector_prompt_test_v2.txt exactly as it exists on disk — every phase, rule, vocabulary entry, and threshold above is copied from that file, not paraphrased or reconstructed.
  • This is not the prompt behind the headline 14,472-trace corpus. The 6K-SFT / 4.2K-GRPO / 4.2K-held-out pool ([[Data Corpus]]) was generated by generate_realiad_traces_v4.py loading the older prompts/inspector_prompt.txt — a simpler 3–5 sentence template with no explicit six-phase structure, no self-scoring rubric, and no auto-reject rules (it even instructs the model to focus "due to prior guidance regarding expected defect locations," which is the metadata-leakage failure mode this newer prompt was written to eliminate). This six-phase, structured prompt is the real, current one — loaded by generate_variety_traces.py for the Real-IAD-Variety extension that feeds Rollout STaR.
  • Any thesis or write-up text describing the headline corpus as built on a labelled "six-phase template" is describing this file's structure conceptually, not the prompt that actually produced that specific corpus — see CLAIMS_EVIDENCE.md / UNVERIFIED.md in the repo for the full discrepancy audit.
