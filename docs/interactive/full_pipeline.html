From Real-IAD pixels to an explainable inspector

One pipeline, four training-relevant stages: distill Gemini's reasoning onto Qwen2.5-VL with SFT, sharpen it with GRPO reinforcement learning, then curate the model's own rollouts — twice, at two different scales — to build the next round of training data. A separate explainability judge checks whether the best model's reasoning is actually trustworthy, not just accurate. Every number below is read from the eval JSONs / dataset files on disk, not the thesis prose.

Stage 00 · Data Generation

Turning Real-IAD images into reasoning traces

~14,472 single-pass traces, generated by google/gemini-3-flash-preview (Vertex AI) over Real-IAD product photos — 30 products, C1 camera only, mask-filtered, 50/50 normal/anomalous, stratified with a fixed seed. Each trace is Gemini acting as an inspector: one <think> block, then a structured verdict.

The "6K beats 15K" finding. The 6K SFT split and the full 15K union have the same mean <think> length (~137–141 words) — so SFT-on-6K outperforming SFT-on-15K at fixed compute is a data-count/composition effect, not a verbosity or quality-filtering artifact (no quality filter was applied to shrink 15K → 6K).

The 4-factor grid

Model size (3B/7B) × ViT frozen/unfrozen × corpus size (6K/15K) × teacher-ablation arm. Two results anchor the grid: the headline run (7B‑frozen‑6K, ckpt‑564 → 80.16 / 64.78), and the best raw checkpoint, Arm‑C (82.80 / 72.07) — which comes from curating the rollouts first, covered in Curation I below.

Result

SFT+GRPO Run-2 (ckpt-530): 82.73 / 70.39 BA, and — uniquely among the checkpoints on this page — it was also evaluated on the 4,236-item held-out Real-IAD split: 80.87 BA, statistically close to its in-distribution score. This is the project's overall headline model, and it's the exact checkpoint rolled out in both curation rounds below.

GRPO on top of the already-strong Arm‑C init shows no further gain — roughly 2pp below the Arm‑C init while the reward itself rises, holding across all three advantage-estimator variants tried. GRPO's lift is real starting from the plain 6K‑SFT init, not from the curated‑rollout init.

Curation, round I · 10,236 items, in-distribution

How much curation does a rollout need?

Before GRPO, checkpoint run2/ckpt-530 was rolled out (k=8) on all 10,236 in-distribution SFT+GRPO images, judged, and selectively corrected/rewritten by Gemini. Three SFT training sets were then built from the same rollout pool, each keeping progressively more of the curation output — a clean ablation on how much curation actually matters.

86.7% of the 10,236 rollouts were kept as-is — the same outcome rate later reproduced on the disjoint held-out set in Curation II below, i.e. rollout quality doesn't drop on unseen images.

Curation-depth ablation: RAFT vs. STaR vs. STaR+rewrite

Same rollout pool, same base model, three cuts of how much gets fixed before SFT. Each arm's best checkpoint by mean BA, from the raw eval JSONs.

Arm B (kept + corrected) barely beats Arm A (kept-only) — fixing wrong-conclusion traces alone isn't the lever. Arm C (kept + corrected + rewritten) jumps +3.3 DS‑MVTec / +4.6 VisA over Arm B — grounding the traces that were already right but weakly reasoned is what actually moves accuracy. Arm‑C's checkpoint‑376 becomes both the project's best raw SFT model and the reference init for further GRPO experiments.

Curation, round II · 4,236 held-out items

Does the curation loop generalize to unseen products?

The identical pipeline — same model (run2/ckpt-530), same k=8, same thresholds and prompts — run again on the 4,236-item held-out split the model never trained on. This round feeds the in-progress iteration-2 / Variety-STaR self-training loop, not Arm-C.

Explainability Check

Whose reasoning can you trust?

Balanced accuracy alone can't distinguish two models that get the same answer for different reasons. On the 398 images where both Arm-C SFT and IAD-R1 (external baseline) answer correctly, a blind Gemini-3-Flash judge — not told which model wrote which trace — scored each trace's <think> block on five faithfulness axes.

Mean of 5 judged axes (visual grounding, defect faithfulness, evidence-before-conclusion, coherence, conciseness), 0–10 total. On DS-MVTec, 29 of IAD-R1's 99 traces are the bare word "Yes" — no reasoning to grade; excluding those, the gap narrows from +4.85 to a more honest +3.07. On VisA, no traces are bare and the gap holds at +2.27 unadjusted.

Read before citing. Single judge pass (k=1, not median-of-3); reference-guided plausibility, not a mechanistic/perturbation-based faithfulness test; the judge model family (Gemini) overlaps the trace-generation model family — blind-to-authorship scoring mitigates but doesn't eliminate this.

Scope & caveats
  • Two curation rounds, easy to conflate. Round I (10,236 in-distribution items) already shipped and directly produced Arm-C, the best raw model in the project. Round II (4,236 held-out items) is the separate, still-in-progress iteration-2 / Variety-STaR loop. Both use the identical rollout→judge→correct/rewrite mechanics and the same source checkpoint (run2/ckpt-530), which is why they're presented side by side here — but only Round I has produced a released model.
  • Corpus generation model discrepancy. scripts/00_generate/README.md confirms the generator calls google/gemini-3-flash-preview via Vertex AI; some thesis prose says "Gemini 2.5-Flash." Tracked, not yet reconciled everywhere.
  • Six-phase prompt scope. The six-phase structured prompt documented in Stage 00 above is real and on-disk, but is the Variety-extension generator's prompt, not the one that produced the headline 14,472-trace corpus — see the dedicated page for the full discrepancy audit.
  • Arm A/B/C's per-checkpoint BA numbers above are this page's own selection (best mean BA across DS-MVTec/VisA, recomputed from results/eval_ba_inventory.txt) — Arm-C's ckpt-376 is the only one of the three formally called out as a project checkpoint elsewhere.
  • Model weights aren't in git — only eval JSONs and configs. The four released checkpoints are the only weights available, via Hugging Face.
